Codex Bridge 1.2.2-rc.2 — backend 1.2.0-rc.2, AI Companions 0.4.6

Install and Deploy the add-on with Vortex. No Apply.cmd is needed. Install the base mod and its author-specified dependencies separately. The conversation features also work with Gemini and other supported providers; Codex CLI is required only when you choose Codex.

First-time Codex setup:
1. Install the official Codex CLI separately. The reviewed public CLI is 0.166.0; required isolation flags and tool controls are checked at startup. An older/incompatible CLI is refused. Sign in with your own supported ChatGPT account; usage limits and model availability apply. No subscription, CLI executable, Python executable or credentials are supplied by this add-on.
2. Run Login.cmd in this folder once. This is an explicit interactive sign-in, not an installation/apply step. It uses the dedicated %LOCALAPPDATA%/AiNpcCodexBridge/codex-home directory and the official codex login command. It never copies another login's auth files. If upgrading a shared-home configuration, the helper asks before backing up config.json and switching codex_home to isolated.
3. In the base mod, select Custom as Conversation provider, base URL http://127.0.0.1:17865/v1, and model codex-default. Leave its API-key field empty. The local transport credential is generated and attached automatically; do not paste it into the game or share it.
4. Content packs > Codex Bridge offers CLI default (recommended), reasoning Auto (CLI default), and Custom model from config.json. New users inherit CLI defaults, not a developer's model. Old saved model/effort indices keep their meanings and are labelled Legacy/account dependent. Availability and effort support depend on the account and CLI. Unsupported combinations keep the last applied backend settings and show an error.

Advanced configuration lives in %LOCALAPPDATA%/AiNpcCodexBridge/config.json. Set model to an identifier supported by your own CLI, then select Custom model from config.json. Model identifiers contain only letters, numbers, underscore, period or hyphen. A non-default port is respected by the add-on; only the shipped default Codex URL is remapped. Explicit unrelated Custom URLs are untouched. Stop your owned backend before changing host/port/home. host must remain 127.0.0.1.

The backend starts lazily on a local Codex completion request or explicit model-setting change. Installing this package while using Gemini does not start Codex or repeatedly launch missing-CLI checks. A session-owned backend stops with the conversation service. A manually started compatible authenticated backend can be reused without claiming its PID or stopping it. Old unauthenticated bridges are refused with a request to stop/restart them yourself; another service on the port is not adopted or killed. Start.cmd, Stop.cmd, status.ps1 and check.ps1 remain optional diagnostics for the owned service.

Existing config.json and selection.json are preserved. A missing codex_home in an older config retains its shared-home setting and displays a legacy warning. Set codex_home to isolated via Login.cmd to separate it. AGENTS.md / AGENTS.override.md in the selected Codex home are refused without reading their contents. Keep the dedicated home free of personal instructions and skills. Login.cmd never runs automatically and no browser login is opened by game startup.

Security and privacy: requests use a dedicated temporary work folder, ephemeral CLI sessions, read-only sandbox, never-approve policy, disabled shell/web/MCP/skill/subagent features and restricted environment variables. The upstream CLI may still register limited native tools such as apply_patch or a clock; this is not a guarantee of zero advertised tools or zero file-read capability. Upstream read-only/never policy rejects write patches. Any unexpected tool event aborts the request. Do not submit real secrets in fictional dialogue. Game dialogue/context and optional scene images are sent to OpenAI through your own CLI login. This is an unofficial community integration, not an OpenAI product endorsement or an unlimited/free service.

Local HTTP is IPv4-loopback only. It requires a per-user random token for completions/settings/models/shutdown. Before disclosing Bearer, Node and PowerShell verify a fresh, port-bound challenge HMAC from the server. Foreign Origin/Host values and redirects are rejected. The token stays in local-token.json under the Windows user profile; it is never placed in a URL, prompt, status log or package. It does not isolate you from malicious software running as the same Windows user, broken profile ACLs or every possible local race.

At most 8 HTTP handlers, 1 active generation and 30 admitted completions per minute are allowed by default. Request/body/image/output sizes and deadlines are bounded. The bridge does not log prompts, replies, image bytes, event streams, API keys or authentication tokens. Only fixed diagnostics and non-secret readiness metadata are logged. Do not upload your state directory when reporting bugs.

Fixtures use synthetic text and disposable local services. They do not prove gameplay compatibility, voice quality or actual account model access.
